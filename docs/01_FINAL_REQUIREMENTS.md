# 最终需求：以此为准

## 1. 目的和范围

- 一个现有微信群、几十人内部娱乐。全体参与者共用一套被评分头像和榜单。
- 不做多群隔离、群口令、入场审批或自动核验微信群成员。用户明确放弃这些限制。
- 当前网页只是先行参考；后续目标是微信小程序。
- 不要求商城、收款、聊天、通知、分享营销或群机器人。

## 2. 必须区分的两个实体

**评分者 participant**：操作小程序的微信用户。同一微信账号在本小程序中应对应同一用户、一份当前分配。修改自己的头像/昵称不应变成新账号。

**被评分头像 target**：初始 13 张头像，每张是独立评分对象。不绑定对应微信号，不需要认领，不显示昵称。即便真人本人没有登录，也可以对这张头像评分。“可以给自己分配”意味着可以给大家认作自己的那张头像分配，系统不需要知道它对应谁。

不能把评分者账户集合当成 target 集合。评分者资料头像也不应自动成为新 target。

## 3. 分配规则

- 每个评分者总额度固定为 100 点。
- 对单个 target 只能填 0～100 的非负整数，允许一张头像获得全部 100 点。
- 一份方案所有 target 点数总和必须**恰好 100** 才可提交。
- 没分配到的 target 默认 0；不必逐张显式录入 0。
- 填写或修改任意一张头像的值，立即更新已分配总数和剩余额度。
- 用户可以随时修改自己的方案。当前计分只取每人最新一次有效提交，不把多次提交当成多个评分者。
- 草稿不影响公共分数，成功提交才生效；修改中的旧有效方案继续参与计分（这是网页采用的合理交互约定，用户未要求反向撤销旧分配）。
- 方案跨天保留，不每日清空；只要没有新的有效分配变动，已有计分结果持续沿用。其他人首次提交或修改仍会改变公共均分。

## 4. 实时瘤度分

- 某 target 收到的最新有效分配总和 ÷ 已经提交有效分配的评分者人数。
- 未提交者不计入分母；已提交者给某 target 的 0 分计入分母。
- 没有任何有效提交时，全部 target 分数为 0.0，不出现除零错误。
- 所有实时瘤度分保留 **1 位小数**，先四舍五入，再用这个值排名和判断同分。
- 例如原始均分 8.31 和 8.34 都成为 8.3，须算并列。
- 同分名次采用竞赛名次：1、2、2、4，而不是 1、2、2、3。
- 所有 target 都显示在榜单，包括 0 分和未来新上传的头像。**不再执行 0 分不上榜**。
- 无需先分配/提交 100 点才能看榜。**用户明确取消“未提交不可看榜”**。

## 5. 公开或隐藏

- 每次提交分配都要主动选择“公开”或“隐藏”后才能提交，没有自动默认选项。
- 提交后可以修改公开状态，不必改动分配值。
- 公开方案展示**评分者本人**的头像、昵称及分配明细；被评分 target 依旧只展示头像，没有昵称。
- 隐藏方案不向其他用户暴露分配明细，但仍完整参与平均分计算和每日结算。
- 网页公开明细仅列出正分项，并说明其余头像为 0；这是紧凑展示方式，不改变完整分配含义。
- 客户端隐藏控件不等于明细保密：数据接口也必须限制公开字段。

## 6. 上传头像

- 提供明显的“上传新头像”入口，**所有登录用户**可使用。
- 新增后成为新的 target，不绑定微信账号、不显示昵称，初始霸榜瘤值 0.0。
- 已提交方案继续有效，对新 target 默认给 0 分，原有评分者仍计入分母。
- 想给新 target 分配的人，需要调整自己的总计 100 点方案并提交。
- **第一版暂不提供删除功能**。没有确认更换已有 target 图片、合并相似头像等管理功能，不要擅自新增。
- 网页采用“立即加入、中心裁切为正方形”的实现；这些具体处理细节并非用户单独指定，迁移时可用原生选图裁切保持易用。

## 7. 三个主界面

1. **分配瘤度**：同页看到排行榜、各 target 当前分数、自己的分配值、剩余额度，选择公开/隐藏并提交；可修改当前方案、上传新头像。
2. **实时排行榜**：独立的只读排行榜，展示名次、target 头像和实时瘤度分，不带分配输入框。
3. **霸榜瘤值**：展示每张 target 的累计霸榜积分，并有“每日前三名”入口，按日期查看历史结算记录。

辅助入口：评分者自己的资料、查看其他人公开的方案、玩法说明。它们在网页中为弹窗，不要求一定做成额外主 Tab。

## 8. 每日结算与累计

- 时区北京时间 Asia/Shanghai，每天 **23:59** 保存当天排行榜前三奖励名次的记录。
- 基础奖励：冠军 6 点、亚军 3 点、季军 1 点；第四名及以后基础奖励 0。
- 并列者平分其占用名次的奖励池；详见算法文档。
- 当前实时瘤度分为 0 的头像，不获得霸榜积分。若全为 0，当天不发积分。
- 每日得到的霸榜奖励四舍五入为 1 位小数，再累计。累计霸榜瘤值显示 1 位小数。
- 初始及新增 target 的霸榜瘤值为 0；长期累加，不按天清空。
- 当日结算结果及已发积分固定。之后修改分配只影响当前和未来，不重写过去的历史结果。
- 并列可能使每日记录/获奖 target 超过 3 个，不得直接截取前三张图片。
- 旧分配每日继续参与结算；并非只有当天修改或当天提交的人有效。

## 9. 运行和身份说明

- 小程序目标：微信登录识别评分者，而非浏览器 Cookie。昵称头像只是用户资料，不能作为唯一账户键。
- 用户对群身份校验要求不高，已经明确不要口令/群成员验证；不要把它重新引入。
- 当前网页后台在用户电脑上运行，关机期间不能访问。23:59 开机还必须后台服务运行、电脑未休眠；重启可补算。
- 小程序不能依赖用户持续打开页面，也不能把手机本地计时器当服务端每日调度。实际部署方式尚未选定。
